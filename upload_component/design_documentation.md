# 插件上传与发布页面 UI 设计文档

## 1. 设计概述

### 1.1 设计目标
插件上传与发布页面是 Plugin as a Service Hub 平台的核心功能模块之一，专为插件开发者设计，旨在提供一个直观、高效的界面，帮助开发者完成插件的上传、配置、定价和发布全流程。本设计遵循以下目标：

- 提供清晰的步骤引导，降低开发者上传和发布插件的门槛
- 支持多种插件上传方式，满足不同开发者的需求
- 提供全面的配置选项，确保插件能够正确部署和运行
- 支持灵活的定价和销售模式，最大化开发者收益
- 确保界面直观易用，提升用户体验

### 1.2 用户角色
本页面主要面向"插件开发者"这一用户角色，他们需要能够上传插件、配置部署方式、设置定价、管理插件版本等。

### 1.3 设计原则
- **引导式设计**：通过分步骤引导开发者完成复杂流程
- **直观交互**：使用清晰的视觉提示和交互元素
- **即时反馈**：提供实时预览和验证反馈
- **灵活配置**：支持多种上传和部署方式
- **一致性**：保持与平台整体设计风格的一致

## 2. 页面结构

### 2.1 整体布局
页面采用垂直流式布局，包含以下主要部分：
- 顶部导航栏
- 页面标题和描述
- 步骤指示器
- 步骤内容区域
- 底部操作按钮
- 页脚

### 2.2 步骤流程
整个插件上传与发布流程分为5个主要步骤：
1. **上传插件**：选择上传方式并上传插件文件
2. **基本信息**：填写插件名称、描述、标签等基本信息
3. **部署配置**：配置插件的部署方式和资源需求
4. **定价与销售**：设置销售模式、价格和促销策略
5. **发布确认**：最终检查和确认发布

## 3. 详细设计

### 3.1 步骤1：上传插件

#### 3.1.1 上传方式选择
提供三种上传方式，以卡片形式展示：
- **Dockerfile 上传**：上传包含 Dockerfile 的项目目录
- **镜像 TAR 包**：上传预构建的 Docker 镜像
- **GitHub 仓库**：关联 GitHub 仓库自动拉取代码

设计特点：
- 卡片式布局，突出各选项特点
- 激活状态明显区分
- 简洁的图标和描述

#### 3.1.2 文件上传区域
- 拖放上传区域，支持文件拖放和点击上传
- 清晰的文件格式和大小限制提示
- 上传进度指示

### 3.2 步骤2：基本信息

#### 3.2.1 基础信息表单
包含以下字段：
- 插件名称（必填）
- 插件标识符（必填）
- 插件简介（必填）
- 标签（可选，最多5个）

#### 3.2.2 详细描述
- 富文本编辑器，支持 Markdown 格式
- 支持插入图片、代码块和表格

#### 3.2.3 插件截图
- 图片上传区域，支持多张截图
- 建议尺寸提示
- 缩略图预览

#### 3.2.4 实时预览
- 实时显示插件卡片预览效果
- 随表单输入更新

### 3.3 步骤3：部署配置

#### 3.3.1 配置选项卡
使用选项卡组织不同类别的配置：
- 基础配置
- 环境变量
- 网络设置
- 存储配置
- 高级选项

#### 3.3.2 部署方式选择
提供多种部署方式选择：
- Docker 容器
- Kubernetes
- iframe 嵌入
- API 接入

#### 3.3.3 资源配置
- CPU 需求选择
- 内存需求选择
- 端口和协议配置

### 3.4 步骤4：定价与销售

#### 3.4.1 销售模式选择
提供多种销售模式：
- 免费
- 一次性付费
- 订阅制
- SLA增值服务
- 源码出售

#### 3.4.2 价格设置
- 价格输入
- 计费周期选择（一次性/月付/年付）

#### 3.4.3 试用设置
- 启用/禁用免费试用
- 试用天数设置

#### 3.4.4 促销设置
- 启用/禁用促销价格
- 促销价格输入
- 促销时间范围设置

### 3.5 步骤5：发布确认

#### 3.5.1 发布前检查
- 检查项列表，包含状态指示
- 成功/警告/错误状态的视觉区分

#### 3.5.2 发布协议
- 协议内容展示
- 同意协议复选框

#### 3.5.3 发布按钮
- 只有在同意协议后才启用
- 突出的视觉样式

## 4. 交互设计

### 4.1 步骤导航
- 步骤指示器显示当前进度
- 完成步骤标记为已完成状态
- 当前步骤高亮显示
- 支持点击已完成步骤返回修改

### 4.2 表单交互
- 实时字段验证
- 错误提示直接显示在相关字段下方
- 必填字段明确标记
- 自动保存草稿功能

### 4.3 按钮操作
- 主要操作（下一步/发布）使用主色调按钮
- 次要操作（上一步/保存草稿）使用次要样式
- 按钮位置保持一致，便于用户操作

## 5. 视觉设计

### 5.1 色彩方案
- 主色调：靛蓝色 (#4f46e5)
- 成功状态：绿色 (#10b981)
- 警告状态：黄色 (#f59e0b)
- 错误状态：红色 (#ef4444)
- 中性色：灰度梯度，从 #f9fafb 到 #111827

### 5.2 排版
- 主要字体：Inter 或系统无衬线字体
- 代码字体：JetBrains Mono 或系统等宽字体
- 清晰的层次结构，使用不同大小和粗细区分

### 5.3 组件样式
- 圆角边框：0.5rem
- 一致的阴影效果
- 卡片式布局
- 清晰的边框和分隔线

## 6. 响应式设计

### 6.1 桌面布局
- 最大宽度 1200px，居中对齐
- 多列表单布局
- 并排的卡片和选项

### 6.2 平板布局
- 适应性调整为单列或双列
- 保持关键元素可见性

### 6.3 移动布局
- 单列布局
- 折叠部分复杂表单
- 优化触摸交互

## 7. 实现建议

### 7.1 技术栈
- HTML5 + CSS3
- 响应式框架（如 Tailwind CSS）
- JavaScript 用于交互逻辑
- 可选的前端框架（如 React, Vue）

### 7.2 组件复用
- 表单控件
- 卡片组件
- 步骤指示器
- 上传组件
- 预览组件

### 7.3 性能优化
- 延迟加载非关键资源
- 表单状态本地存储
- 优化图片上传和处理

## 8. 可访问性考虑

### 8.1 键盘导航
- 确保所有交互元素可通过键盘访问
- 逻辑的 Tab 顺序

### 8.2 屏幕阅读器支持
- 适当的 ARIA 标签
- 语义化 HTML 结构

### 8.3 颜色对比度
- 符合 WCAG 2.1 AA 标准的颜色对比度
- 不仅依赖颜色传达信息

## 9. 未来扩展

### 9.1 潜在功能增强
- 插件版本管理界面
- 更详细的分析和统计数据
- A/B 测试价格策略
- 批量上传和管理功能

### 9.2 集成机会
- 与 CI/CD 系统集成
- 与代码仓库深度集成
- 与支付系统集成
- 与用户反馈系统集成

## 10. 总结

插件上传与发布页面设计旨在提供一个直观、高效的界面，帮助开发者完成从上传到发布的全流程。通过分步骤引导、清晰的视觉设计和流畅的交互，降低了开发者的使用门槛，提升了用户体验。同时，设计考虑了响应式布局、可访问性和未来扩展性，确保了界面的适用性和可持续发展。
